Saya ingin mengubah sistem login Google menjadi login dengan nomor WhatsApp, dan menambahkan akun pengguna tenant.

Kondisi saat ini:
- Login page masih ada tombol “Masuk dengan Google”
- Dev login owner/admin/finance/cashier sudah berjalan
- Role saat ini: owner, admin, finance, cashier
- Sistem sudah multi-site:
  1. Sport Center Bandara
  2. TOD M1 Bandara
- Data tenant, booking, invoice, payment, laporan sudah ada
- Ada table tenants untuk penyewa/kios
- Saya ingin tenant/penyewa bisa login dan hanya melihat datanya sendiri

Tujuan:
1. Ganti login Google menjadi login dengan nomor WhatsApp.
2. Tambahkan role baru tenant_user.
3. Tenant user hanya bisa melihat data milik tenant yang terhubung dengan akunnya.
4. Admin tetap bisa membuat/mengelola akun tenant.
5. Jangan merusak dev login owner/admin/finance/cashier.
6. Jangan hapus Google OAuth permanen dulu, cukup disable/hide dari UI atau jadikan optional untuk nanti.

FASE 2 — Login dengan Nomor WhatsApp

Buat flow login WhatsApp berbasis OTP.

Endpoint baru:
1. POST /api/auth/whatsapp/request-otp
Body:
{
  "phoneNumber": "08123456789"
}

Logic:
- Normalisasi nomor ke format Indonesia, misalnya 628123456789.
- Cek user dengan phone_number tersebut.
- Jika user tidak ada atau inactive, jangan bocorkan detail. Return message umum:
  “Jika nomor terdaftar, kode OTP akan dikirim.”
- Generate OTP 6 digit.
- Simpan OTP hash, bukan plaintext.
- OTP expired dalam 5 menit.
- Batasi request OTP dengan rate limit.
- Untuk development, boleh return devOtp di response jika ENABLE_DEV_LOGIN=true atau NODE_ENV=development.
- Untuk production, OTP harus dikirim via provider WhatsApp, nanti bisa Fonnte atau provider lain.

2. POST /api/auth/whatsapp/verify-otp
Body:
{
  "phoneNumber": "08123456789",
  "otp": "123456"
}

Logic:
- Verifikasi OTP.
- Jika benar, login session user menggunakan req.login.
- Update last_login_at dan phone_verified_at jika belum ada.
- Return user dan role.

3. POST /api/auth/logout
Tetap berjalan.

4. GET /api/auth/me
Harus return:
- id
- name
- phoneNumber
- email jika ada
- role
- allowedSites
- tenantAccess jika role tenant_user

FASE 8 — Rate Limit dan Security

Tambahkan rate limit:
1. request OTP:
   - 5 request / 15 menit per nomor
   - 20 request / 15 menit per IP

2. verify OTP:
   - 10 request / 15 menit per nomor/IP

3. OTP:
   - simpan hash
   - expired 5 menit
   - maksimal salah 5 kali
   - setelah berhasil, OTP tidak bisa dipakai ulang

4. Audit log:
   - whatsapp_otp_requested
   - whatsapp_login_success
   - whatsapp_login_failed
   - tenant_user_created
   - tenant_user_deactivated

Jangan log OTP plaintext.
